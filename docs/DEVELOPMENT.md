# 开发与维护

本分支为独立 Rust 工程，根目录就是 Cargo 工程。原 Python 参考实现、调试抓包、真机脚本、构建目录和个人运行配置不进入本分支。

## 模块

| 模块 | 职责 |
| --- | --- |
| web / assets | Axum 路由、静态 Web、访问令牌与请求历史界面 |
| service | 会话隔离、32 个会话上限、四路读取、独占验证、超时和取消统计 |
| network | 原生 HTTP/TLS、重定向、Cookie、系统 DNS / 可配置 DoH、显式代理与请求级 IP 映射 |
| engine | 从初始请求到独立复读目标页面的完整协议流程 |
| constants / compiler / compiler_profiles / data | 静态语法、常量恢复、有限模型和数据校验 |
| literal_strings | 对已审核语法形状进行有界字符串解码；拒绝变形配方，不调用网站函数或宿主 API |
| catalog / models / model_geometry / surface / locale / semantics / declared | 按当轮输入计算已识别任务 |
| wire / completion / http_tasks | 编解码、后续阶段判定、受约束的 HTTP 子任务 |
| sources / assets/*-parser.js | 动态书源导出及各站点 HTML 解析 |
| embedded | 已知站点的嵌入式验证声明、搜索表单与验证 Cookie 约束 |

profiles 是显式声明、公式和不可变协议布局，不是已计算的浏览器指纹或可复用验证凭证。当前软件模型不声称测量了真实浏览器或发生了人工交互。

静态常量分析中的数组、对象采用写时复制，作用域快照共享只读数据，受限的局部写入先取得独立副本；不能让一次求值改变后续求值的作用域。作用域构建只在需要分析绑定时发布快照，候选筛选先检查语法再求值，避免冷进程反复复制大型常量表。主验证脚本的 managedProtocol 与组件的 frameInitialization 均返回 analysisMs 和 compiledLayoutReused，便于区分首次解析与布局复用；这些诊断耗时不参与协议任务计时。

作用域的绑定表本身也采用写时复制，读取单个名字不复制数千项继承绑定。构建过程中只在有效绑定的求值前发布快照，允许重入辅助函数读取已完成的绑定；求值结束、真正写入前释放这份临时快照，避免逐槽填充数组时反复复制整张表。调用方已持有的快照仍保留独立视图。闭合字面量算式沿用原步数、深度和取消检查，直接求值而不构建无关作用域；含变量或函数调用的表达式保留完整绑定解析。

函数参数及局部写入使用稀疏覆盖层，继承的大作用域保持只读共享；小覆盖层写时复制，最多八层，达到上限时合并当前可见绑定。重名绑定（包括 Dynamic）遮蔽父层，修改继承数组／对象时只分离目标绑定及其数据，不能改变已发布的快照。相同编码程序只恢复一次候选，同轮多个程序复用经过当前语法证明的辅助函数名称，仍逐程序校验邻接密钥及唯一性。

内置的组件布局来自完整编译结果一致的公开初始化程序；只在当前程序摘要、版本及 helper 均匹配时复用。布局不含请求配置、Cookie、动态任务输入或答案，字母表、模数和提交路径仍逐次读取当前脚本。阶段诊断 phaseMs 与 taskDurationsMs 只记录本机耗时，不参与提交字段或改变原有任务计时和工作量预算。

父初始化程序的布局身份不依赖封装 CV 声明的源码拼写。69 份公开脚本的完整编译输出按程序摘要分组，除声明拼写外归并为六套相同布局；复用时仍解析当前声明、核对词法绑定、八个 CV 数值及模型版本，变化或缺少证明时报错。声明依赖先尝试不含调用／重写的有界常量路径，不能证明时恢复完整分析；没有跳过认证。语法遍历使用 TreeCursor 保持原先序及函数边界。编码字面量解码在一次遍历中建立作用域索引：按词法函数归属解析调用绑定（方法透明），按函数与方法边界从同一索引推导每个作用域直接绑定的名字，不再逐作用域重新遍历；热路径以节点类型编号代替字符串比较。替换只记录按原坐标倒序排列的编辑，`Prepared::tree` 在编译或完整密钥回退需要时才把编辑应用到原树并增量解析；布局复用路径通常不需要编辑后的树。仍检查语法错误及取消。

声明依赖仅在同一次不可变语法分析中记忆已证明的值，上限 4096 项，不跨脚本或请求保存；有活动证明覆盖时禁用该路径，避免把替代操作数与原声明混用。完整协议布局的动态缓存按归一化结果去重，当前声明的拼写仅随本次 Plan 返回，不成为新的缓存项。

组件边界模型 v4 按已经证明的固定分派顺序核对闭包头部，不能以源码位置替代实际顺序；捕获循环必须单独归属当前计数，外层固定分派循环不能被当作捕获循环。选择器转发允许直接传当前状态或单项数组包装。字符读取经过静态转发时，以有限输入核对透传结果，并记录当前字节函数的实际调用次数，必须恰好一次。密钥切片同时识别赋值与变量声明，仍证明同目标、16 字节跨度及邻接认证密钥。

短伪候选也可能遮住长 CSS 或 Unicode 字符串。补读保留每轮 8 MiB 解码预算及原有边界追踪上限；非短候选须从已知锚点经至少两条已识别指令抵达，并在另一侧抵达已知锚点或完整校验通过的 flow-call，核对当前指令密钥。原有长字符串／打包数据保护保持，未知路径不能靠增加任务白名单或丢弃字段通过。

同一语法树的词法作用域归属按先序建立索引，函数、箭头和方法的边界与逐级查找保持一致；外层作用域仍排除当前函数本身。指令边界追踪的字符串／打包区域查询使用排序位置索引，保留重复位置与半开区间；256 个可能解码密钥用固定大小位集去重，避免每个字节位置分配哈希集合。

精确布局命中的新父协议只把当前 CV 校验与首次 HTTP 请求并行。首次请求使用当轮唯一的字母表、模数和路径以及精确程序布局；必须等待当前词法声明、八个 CV 值和版本校验通过后，才能解码响应并进入后续任务。两路共用原截止时间，任一路失败立即丢弃另一路 future，沿用 CPU 协作取消，不启动游离后台任务。完整编译及仅分析模式仍先完成校验。此路径 analysisMs 记录布局准备，layoutValidationOverlapped 标明余下校验已计入首次提交墙钟时长；totalMs 始终包含两路全部工作，不将重叠耗时相加，也不修改协议任务计时字段。

同一响应 Document 也共享一次原始 JavaScript 语法解析，初始化程序预处理复用该树，语言配置读取直接使用原树；增量编辑使用独立快照，不能改动共享树。配置名称在原文中只有一个出现位置时，以树的位置查询精确定位实际赋值，仍使用相同的字面量读取；名称重复、仅出现在字符串／注释中或特殊嵌入配置均保留原完整扫描。缓存仅属于当前不可变响应，不按 URL 保存脚本或正文，不跨请求共享动态语法或配置。

密钥辅助函数识别按规范化目标引用一次建立赋值索引，仍以原函数体边界筛选并保留候选唯一性。状态多项式只复用解析出的引用位置，逐状态数值仍重新计算并对全部 256 个状态校验，不复用挑战答案。

字符解码的 XOR 可被写成 `(a | b) - (a & b)` 并经过局部别名或静态算术转发。字节模型要求唯一的当前字节读取、唯一的 16 位种子右移，限制源码、节点和调用数量；额外调用须通过已有算术模型，拒绝分支、循环、未知调用和非局部写入。64 组字节／种子输入分别核对两种运算顺序，必须唯一，不能仅凭局部语法决定先后。密钥切片允许调用前有局部逗号表达式，仍校验转发参数及 16 字节范围；邻接密钥和摘要校验保留，不扫描任意 helper 名称或试切字符顺序。

布局缓存的冷编译串行合并，取得编译权后重新查询，写入前检查重复；热读取不等待编译锁。完全相同的布局不构成歧义，内容冲突仍报错。运行期最多保留 32 项，失败或已取消的编译不写入缓存。 新编译并写入内存的布局同时持久化到 `data::layout_store`（`--layout-cache-dir`）：文件内容就是内存条目本身，另加格式版本与编译它的程序构建标识；启动时只加载同一构建写出的条目，经 `normalize` 校验后与内嵌布局合并，匹配、歧义和 32 项上限规则完全相同。其他构建、损坏、超过 1 MiB 或结构不符的文件跳过并计数，不中断启动；写入先落临时文件再改名，按内容命名避免重复，多出的最旧文件清理。Unix 上目录必须为当前用户私有（0700），否则不启用。缓存不含请求参数、Cookie、任务输入或答案，不是网页缓存。预处理后的源码直接进入编译核心，不再次解码；编码字符串按原位置顺序拼接，并在分配最终字符串前核对解码尺寸。

解析、本地任务和工作量计算共用进程级 CPU 名额，上限为可用逻辑 CPU 数与 6 的较小值，至少为 1；状态接口 runtime.cpuWorkerLimit 返回该值。多请求不能各自再占满六路计算。工作量搜索使用实际工作数划分互不重叠的计数序列，提交实际工作数、实际尝试次数和结果，仍保留原有协议任务计时规则。

CPU 排队和执行都受原请求截止时间约束。等待 future 被丢弃时通知同步计算停止，正在执行的工作持有名额直到真正退出；语法解析进度、常量求值、模型模块和哈希循环设有取消检查，已审核算术模块通过 epoch 中断检查取消。取消是协作式的：短的本机库调用需要返回到检查点，不能承诺线程在超时瞬间消失。HTTP 子任务组也随请求退出取消，避免丢弃句柄后继续等待网络。CPU 超时诊断保留 source=cpu，不误标为网络错误。

计算池中的布局、Wasm 和 HTML 缓存锁使用同一等待辅助函数：锁竞争时阻塞工作线程暂时归还 CPU 名额，取得锁后先重新排队取得名额，再访问数据或继续计算。等待锁和重新排队均检查原取消状态与总时限；取消时释放取得的锁，不发布半成品。工作组逐个持有名额，任一时刻的实际计算仍受原进程上限约束。

协议响应解码、字面量扫描、目录构建和 HTTP 任务描述分析在计算池执行；扫描循环也检查取消。组件响应和目录在阶段间移动所有权，Plan 以只读 Arc 共享，避免在异步请求线程进入计算队列前复制整个响应、规则和目录。仍并行发起 HTTP 子任务，再计算本地任务。

状态接口在短锁内取得请求计数和最近记录快照，释放统计锁后才读取进程内存和构建信息；Web 路由将整个状态收集放到阻塞工作线程。系统查询慢时，不持有请求登记／完成所需的统计锁，也不直接阻塞异步请求线程。

图片请求按实际 PNG/JPEG/GIF/WebP/AVIF 字节特征跳过文字解码，识别规则与最终图片验收共用；文字策略属于请求上下文，不改变共享会话。图片地址返回的 HTML 验证页仍走正常验证，错误的 image MIME 只有在正文呈现 HTML／script 开头结构时才允许分析。原始图片与 HTML 返回均直接转移正文缓冲区，不先构造 JSON body 再删除或复制；Document 仍有其他使用者时才复制文字，保证共享读取不受破坏。

返回数据整理与 JSON 接口的完整序列化进入 CPU 池，沿用原截止时间，阶段为 preparingResponse。JSON 字符串拷贝分块检查取消，耗时字段在主体序列化和缓冲区预留后填写；预留空间避免小尾字段导致请求线程重新复制整页。总耗时包含返回数据准备和排队，返回前再次检查截止时间，不包含客户端网络接收时间。仅导出凭证时不生成正文副本。抓包数据通过惰性生成函数进入 capture：关闭抓包时不调用生成／序列化函数，开启时保留原哈希文件名和错误传播。

新初始化程序可能使用独立的字符串字面量编码、局部数组槽位和按位置变化的指令操作码。字面量仅在完整语法配方及词法绑定匹配时解码；静态求值仍限制步数、深度和本地数据写入。操作码模型从当前脚本恢复并核对有限运算，候选密钥保留全部逆像，再以指令类型、数据边界和认证摘要筛选，不任意选择第一个候选。旧格式省略该可选模型并继续使用原字节变换。编译计划通过不等于取得真实网站页面。

台湾小说网的父页面协议 `c787ce48cf6b` 使用新的提交字段及带认证的打包字符串；组件仍可返回 `d2d3316b729e`，两阶段各自解析当轮脚本。初始化状态和 JSON 标记从当前启动程序恢复，最后提交使用新字段及当前响应的继续验证参数。导航表单仍校验字段次序、同源目标和当前页面令牌，不把一次 200 挑战响应当成正文成功。

带认证字符串的初始 CV 从当前声明中恢复，区分同名局部绑定及等价数组槽位，要求唯一且值一致；布局复用同时核对当前源码中的声明。解码先核对长度、字符顺序及 BLAKE3 认证标签，再释放明文打包字符串，沿用扫描预算和取消检查。状态转移多个逆像汇合成相同解码密钥时只计算一次；不同解码候选仍保留歧义检查。

新增静态识别只处理已经约束的语法：一致的惰性字符串缓存、经过参数顺序校验的 `call.call` 转发、固定数组中的执行顺序、分派分支块，以及可证明为整数恒等式的计数循环。执行顺序最多 64 项，拒绝修改顺序或计数器；计数循环直接使用证明结果，不运行原循环。没有引入网站脚本执行器、浏览器运行依赖、授权状态缓存或额外重试。

状态多项式允许先把当前状态加操作码步长写入标量或固定数组槽位，再计算转移。别名按规范化后的引用匹配，只读取转移之前的唯一赋值；同一变量随后被复用为长度或描述符不会覆盖该证明。恢复后的模型仍对全部 256 个状态验证，错误来源或重复覆盖的别名仍拒绝。

Dispatcher 的 BLAKE3 辅助函数按静态数值和语法结构识别：核对 IV 数组或旧式单独赋值的 IV 常量，以及块步长／块大小值 1024。不能依赖源码含有十进制字面文字，`~-1025` 和等价 XOR 算式必须得到相同识别结果。只在当前函数体内找候选，不混入嵌套函数的常量；字符串／注释中的数字不作为依据。前缀仍从当轮条件表达式恢复，保留候选唯一性和后续摘要校验，不使用固定前缀或放宽重试。失败仅补充辅助函数及前缀候选数量，便于区分漏识别和冲突。

Cookie 上下文按客户端会话名和代理隔离，使用弱引用索引；没有存活来源会话时不会额外保留 Cookie。来源连接、验证锁、读取限额和验证代数独立，禁止把父域 Cookie 的共享误写成多个来源共用“已验证”标志。网络覆盖参数不能清空共享容器内其他域名的凭证。

`NetworkConfig` 的启动默认值是 direct / 系统 DNS（DoH 关闭）。四个启动选项与环境变量提供连接模式、显式代理、DoH 开关及服务器地址；参数覆盖环境，Web 只读，不持久化配置。`network.proxy/doh/mapping` 是单次请求覆盖，缺省继承启动值；保留顶层 proxy/connectTo 兼容，新字段逐项优先。取消全局五 IP、CF 网段分类及线路回退，不因失败静默改变用户指定的路径。

network/config 校验 namespace、精确 authority 与 `*`；network/dns_wire 实现有界 RFC 8484 二进制 DNS，resolver 维护最多 256 项 TTL DNS 缓存及并发查询合并，失败不缓存。DoH 端点由正常系统/代理路径引导，不使用硬编码 IP。代理模式的 DoH 查询也经同一代理，不以本地解析代替远端解析。

network/transport 使用原生 loopback SOCKS 隧道统一 HTTP CONNECT / HTTPS CONNECT / SOCKS5 的连接目标；原因是只覆写解析器不能改变 URL 的显式端口，也不能要求 HTTP 代理按指定 IP 建隧道。原 URL 仍交给 HTTP/TLS 层，Host/SNI/证书校验保持原域名；HTTPS 代理自身使用受信任根证书验证。映射优先于 DNS，精确匹配优先于 `*`，代理及 DoH 基础连接不经过目标映射。

请求 task-local 上下文携带临时 DNS/映射与传输，网络子任务通过 inherit_context 显式继承；请求结束释放，不改变来源/客户端/代理的会话索引或客户端/代理的 Cookie 索引。不同配置不能复用同一映射连接；未覆盖默认设置的请求复用原 Session 连接池。离线测试以独立 DNS、HTTP/SOCKS 代理、跳转和 TLS SNI fixture 验证实际路由，不将策略只做成状态标签。

`CANCELLED` 保留在失败统计中，新增 stage 仅用于定位取消发生于排队、上游读取还是验证。必须在客户端动作与服务端记录之间建立对应，并测试返回该列表项后能否重新加载；不要通过更改统计分母或无限重试来掩盖加载问题。

Wasmtime 只用于匹配已审核摘要、无外部导入且带内存/指令/调用限制的有限算术模块，不是任意网站程序运行入口。Tree-sitter 用于读取语法，不执行 JavaScript。

已审核算术模块的 Engine / Module 在进程内只编译一次，并合并并发首次编译；每次使用仍核对代码摘要，Store、实例、内存、fuel 和测量结果逐次创建，不复用答案。编译等待可取消，首次本机编译返回后也检查截止时间，取消结果不发布。

HTTP 响应文字与其 HTML Facts 由不可变 Document 持有，同一响应的模型、样式和配置分析共享一次解析。解析结束转移结果所有权，避免复制整份脚本。后续 HTTP 响应创建新的 Document，不按 URL 缓存页面，也不跨请求保存正文。配置脚本、语言配置和验证识别均在统一 CPU 池运行，语法解析、节点遍历及字面量读取检查取消；配置成员直接读取已解析语法树，不逐字段重新解析，仍拒绝执行表达式和重复字段。

任务常量范围查询对有序列表使用二分边界，保留重复位置和半开区间语义。列表首次查询检查顺序，任何可变访问都会使该检查失效；兼容乱序输入时保留原顺序筛选，不能把二分查找套在未验证的乱序列表上。运行期构造及目录补充后的列表保持有序。

父页面验证（c787ce48cf6b）自 2026-10-30 起把状态、任务、页面数据、提交输入和最终表单令牌改为不透明 base64url 信封：以 `C[g-v]` 开头，首字节固定为 0x0a，不再含 `-时间戳-1.x.1.1-` 版本标记。旧格式继续兼容；新格式下状态仍由续接常量确定、提交值由重复出现确定、输入由 JSON 字符串确定，剩余两项中与站点密钥常量后续指令相同者为页面数据，另一项为任务标识，两者都必须唯一，否则报错。子框架阶段仍使用旧格式，未放宽其任务识别。

指令边界扫描允许向后跳转：只有跳回本条路径上已经解码过、且指令密钥完全相同的位置时，才把这段循环当作已确认路径，并移除循环体内被误读的操作数字符串（例如误读成 `WebGL2RenderingContext` 的跳转操作数）；跳到未解码位置、密钥不一致或缺少布局描述时仍按原规则中止。空回调任务识别会排除末尾模块范围内共享的根参数区：该区必须恰好由 13 个固定字段名组成，且提交值、随机数和状态三项与本轮子框架参数逐一相等，其他任何意外常量仍会使识别失败。两项都不放宽任务白名单，也不给未知任务补空结果。

短字符串的初次扫描可能被重叠的常量池伪候选遮住。补读除既有标识符规则外，只在候选后紧邻当前布局的 flow-call、指令状态连续且整段校验通过时恢复短字符串，并移除覆盖它的弱候选。保留长字符串和打包数据的保护范围，校验工作量上限为 8 MiB；使用当轮操作码变换、位置和已恢复的指令密钥。不能通过放宽任务白名单或给未知任务填空结果消除 FRAME_DATA_UNSUPPORTED。

整段校验通过的指令区间在首次扫描前取得、排序并合并，初扫与补读都跳过这些区间。不能先让伪打包字符串占据后面的代码，再只从扫描结果删除它；这样已经被遮住的真实字段仍会丢失。相同校验区间在本轮响应内共享，不重复扫描。

有限边界模型从当轮初始化程序恢复常量标签、条件分支、跳转和已审核指令的读取长度；核对地址字节顺序、密钥变换及分支写入的状态字段。支持分支两侧交换、条件取反、共享运算分支，以及携带可变数量数据的函数声明；声明只计算数据长度，最多接受 64 项，不运行函数。常量池属性形式必须匹配池索引分支和两个后缀字节，嵌套展开时只核对外层区域顺序，不推断内部语义。

追踪不计算条件真假，分别核对可能路径，每条路径最多 24 步、每个起点最多 24 个备选、512 字节局部范围及全轮 60000 步预算，继续检查取消。只有后续真实字符串的边界与密钥，或完整指令校验再次吻合后，才排除已确认的操作数；只有确认过的条件分支操作数允许排除伪打包候选，不删除整个跳过的代码区域。组件布局以 boundaryProfileVersion 区分完整边界模型，旧缓存重新编译一次，再沿用原缓存与歧义检查。

无附加载荷的常量分支允许用已审核算术函数计算寄存器地址；仍拒绝额外字节读取、未知调用、分支、循环和构造器。此识别修复使用 boundaryProfileVersion=3，避免复用漏掉空值分支的旧布局。父页面表单只从当前声明的三个连续隐藏输入读取名称及相邻令牌，其他位置的散列或令牌不能参与字段计数；字段唯一性、次序、令牌格式及同源目标检查保持。

新会话验证的连接预热只建立传输层：识别到非 precursor 的托管验证后，会话对固定组件来源 challenges.cloudflare.com 预先建立 TCP（或所配代理隧道），组件首次提交前再为此前验证中出现过的 *.challenges.cloudflare.com 任务主机预连。预连期间不发送 TLS、HTTP 或 Cookie，任务地址仍逐次从当轮程序读取；学习的主机名只是连接提示，最多保留两个。直连模式仅对已预连的主机经会话自己的回环 SOCKS 路由，并在该会话内保持同一路由以稳定 HTTP/2 连接池；代理与映射模式沿用原回环桥及其目标、DNS 和代理策略。每个传输最多 8 个预连，5 秒内未使用即丢弃并按原方式重新拨号；直连多个地址时以 300 毫秒间隔交错尝试，避免单一地址族停顿。

父初始化脚本解析一次后，用原始语法树读取当前封存密钥，同时进行字面量解码；首个提交响应仍在核对完成后才解码。字面量解码只把解码调用替换为字符串，密钥数组若无需这些调用即可求值，两种源码得到同样的数值。原始树读取与布局一致时直接通过；读取失败或结果不同，一律回退到完整的解码源码核对，不能把差异当作通过。封存密钥声明扫描先检查右侧是否为数组字面量，再解析下标目标，避免对大量同对象写入逐个求值。

组件配置与布局分析读取同一份当轮组件脚本，两者并行且都必须成功；配置查找仍解析整个脚本，只深入包含目标名称的语法范围。工作量证明所需的组件页面事实在任务提交请求期间准备，只在响应要求工作量时使用。协议任务时间、工作量预算、等待下限和重试上限不变。
## 本机布局

Windows 测试机只保留一份源码：`services/cf-gateway` 是本仓库 `cf` 分支的 git worktree，所有修改、构建、验收和推送都在这里进行。不要为了诊断再复制一份源码到别处；需要对照旧版本时使用分支、提交或 `git worktree`，诊断用临时二进制可放在 `.local/`。

| 路径 | 内容 | 是否入库 |
| --- | --- | --- |
| `src/ assets/ profiles/ tests/ docs/ scripts/` | 源码、静态资源、协议布局、测试、文档与本机脚本 | 是 |
| `target/` | 唯一的 cargo 构建缓存；release 启用增量编译 | 否 |
| `.local/tools/` | CMake、NASM、libclang；原生依赖（BoringSSL、bindgen）的构建工具 | 否 |
| `.local/bin/` | 19705 服务正在运行的程序、`service.json`、日志 | 否 |
| `.local/evidence/` | 本机验收记录；只放状态、长度、错误和耗时，不放正文、抓包、凭证 | 否 |
| `.cargo/config.toml` | `scripts/dev.ps1 setup` 生成，把 `.local/tools` 提供给 cargo，并为本机 release 打开增量编译 | 否 |

`scripts/dev.ps1` 覆盖日常流程：`setup` 生成本机 cargo 配置；`build` 为 release 构建；`test` 依次执行格式、Rust 测试与 Node 检查；`run` 构建后原位替换 19705 上唯一的服务并等待 `/v1/status`；`push` 在干净的 `cf` 分支上先跑全部检查再推送。Docker 构建只使用 `.dockerignore` 白名单中的文件，本机脚本和配置不会进入镜像。

Linux 开发机不使用这些脚本：安装 CMake、Clang/libclang、NASM 后直接运行下文的检查命令，或使用 Dockerfile。
## 修改约束

1. 先定位失败阶段。HTTP 200、Cookie 颁发、工作量计算完成都不等于取得目标网页。
2. 不能使用旧 Cookie、录制答案、固定任务结果来隐藏协议失败。未知格式应保留明确错误。
3. 不添加网页响应缓存。DNS 元数据和精确程序布局可复用，但不得携带旧密钥、任务输入或答案。
4. 同一总时限覆盖排队、解析、验证与重定向，不能用无界重试伪造稳定性。
5. 新的辅助函数必须进入实际运行路径后再用于对照，避免只在测试中“实现”兼容。
6. 不改阅读应用来掩盖示例解析问题。示例站点应在指定的真实阅读环境中验收。
7. 抓包默认关闭，提交前检查 fixture 和文档，不提交个人令牌、代理密码、账号会话、响应抓包和绝对开发路径。

## 错误复现

Web“请求历史”可筛选处理失败，查看 code、error、details、排队和总耗时。点击“填入工作台”后手动执行；原会话可能已经变化，可以同时比较原会话和新会话。历史只保留 200 条和复现所需参数，不保存页面正文、令牌、Cookie 或代理账号密码。含账号代理需要重新输入。

--capture-dir 仅用于显式本地诊断；输出可能包含短期挑战状态，不能直接上传。用于报告的 URL 应移除临时验证参数。不要为了调试绕过 TLS 证书校验或修改系统代理配置。

## 平台

语言区域模块使用锁定版本的 ICU4X 2.3，数据内嵌于二进制；不再动态加载 Windows ICU DLL 或 Linux ICU .so。月份/时区、语言名称、析取列表和紧凑数字均使用对应组件，语言名称采用带本地化组合模板的接口。遵循 CF_GATEWAY_LOCALE，缺省读取系统语言，C/POSIX 或无语言设置回退 en-US；时区仍由 CF_GATEWAY_TIMEZONE 指定。

Docker 使用 Rust 1.99 / Alpine 3.24 的 musl 目标，构建期的 C/C++ 工具链只用于 TLS 等原生依赖。release 回归与最终程序共用优化依赖，ELF 检查拒绝动态加载器及共享库依赖。运行镜像为 gcr.io/distroless/static:nonroot，不复制任何 ICU 动态库。两架构均需执行实际容器冒烟，不能仅以交叉编译成功作为验收。

ICU4X 的 compact number 和 language display name 接口仍含不稳定 API，版本与数据通过 Cargo.lock 固定；升级时重跑 locale-format-vectors.json。该文件为公开格式化操作数，与站点挑战无关。与旧系统 ICU 对照的 109 组中，三组日语纽约时区名称采用 CLDR 48 的米国東部写法，其旧值和来源链接保留于 fixture；其余字段不放宽断言。
