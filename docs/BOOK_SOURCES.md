# 编写接入示例

服务返回页面，书源负责解析。正式示例统一代取，不把服务签发的 Cookie 假定为可以在不同出口的客户端直接使用。

## 文件

sources.rs 验证服务地址并输出 config、站点标识、服务地址、服务令牌，再拼接 gateway-source.js 与站点 parser。Web 的导入、复制和下载均使用这个导出接口，不维护另一套生成后的书源文件。

gateway-source.js 包含请求、会话、同站 URL 解析、简繁转换辅助和从网页提取发现分类的逻辑。每个 parser 提供：

```js
function search(key, page) { /* 返回书籍数组 */ }
function explore(url, page) { /* 返回书籍数组 */ }
function getBookInfo(book) { /* 返回书籍详情 */ }
function getChapters(book) { /* 返回章节数组 */ }
function getContent(chapter, book, nextChapterUrl) { /* 返回正文 */ }
```

当前示例使用此仓库阅读应用支持的 JS 单文件书源格式，不能假定所有旧版阅读均支持这组回调。

## 请求

cfRead 使用阅读的 java.connect 请求服务端 /fetch，并在 Authorization 请求头携带令牌。目标 URL 作为 url 参数传入，固定 session 保持会话。代理不由示例隐式配置。服务超时 90 秒，阅读网络请求允许 100 秒，以便收到明确的服务错误。

cfUrl 使用 Java URI 解析相对地址，并限制为示例站点，保持路径与查询的原始编码。书名、作者、正文做简繁转换，不能转换 URL 或已经编码的请求字节。图片地址保留网站返回的实际地址。

## 简繁转换

繁体站点的搜索使用 String(java.s2t(String(key)))；输出使用 String(java.t2s(text))。不要添加一份自己的简繁字典。Java 方法返回的 String 在 Rhino 中可能是 Java 对象，对它调用 JavaScript 正则 replace 前须先使用 String(...)，避免 Java 重载选择错误。

## 发现与翻页

cfDiscovery 从站点分类和榜单页面提取名称及链接，仅固定少量导航入口。配置 exploreUrl 调用这段逻辑，由阅读管理发现标签的加载。修改标签后应重新导入书源并刷新发现分类。

cfExplore 保存下一页导航地址，不保存 HTML。仅跟随实际页面的下一页链接，页面无下一页就返回空数组。页面 1 会重置该栏目的导航状态；不同栏目隔离，最多保存 24 组导航。不要对所有 URL 一律拼接 ?page=2，也不要让不分页的首页无限重复。

部分站点本身的相邻分类页会重叠。检查时同时对照原始上游页面，不能误认为服务响应缓存。目录必须使用完整目录接口；保持实际章节顺序，69书吧根据 data-num 升序排列。书籍详情中的章节数可能和实际目录不同，以实际目录条目为准，不伪造缺失章节。

## 验收清单

- 用简体输入搜索，核对书名、作者、简介、封面与详情链接。
- 对所有发现标签检查第一页；有下一页的栏目继续请求，确认请求 URL 实际变化。
- 核对目录首尾章节、顺序、数量以及重复 URL。
- 检查正文首尾，不以“正文非空”代替末段完整性。台湾小说网的 canvas 末段需要正确还原，未知编码应报错。
- 在指定真机的阅读内执行实际回调，不能只在 Node 中通过语法检查就宣称可用。
- 令牌模式与无令牌模式都验证导出，服务地址包含自定义端口和 HTTPS。

69书吧的站内关键词搜索采用独立嵌入式验证，当前未实现。该示例只提供发现、完整书籍 URL 检索、详情、目录与正文，界面和 config 都须保留这一说明。不得将 HTTP 200 的验证提示页解析为空搜索结果或声称已通过。
